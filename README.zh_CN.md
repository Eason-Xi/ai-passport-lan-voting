# 共选 · 局域网投票器

一台电脑主持投票，默认可登记 10 台 AI Passport，设备上限可设为 1～200 台。每道题有 2～6 个单选项。同一设备在同一题中首次确认后锁票。主持人可实时查看统计，公布后每台投票器都会收到最终结果。现场运行只需要局域网。

仓库包含 0.4.0 版投票器固件和电脑主持台。设备使用 ESP32-C3、8 MB Flash 和原板的三个按键。板级驱动沿用 [AI Passport](https://github.com/Eason-Xi/ai-passport)，保留原 MIT 许可证。项目最初的需求见[投票器 PRD 重建版](docs/LAN_Voting_PRD_v0.1_重建版.md)。

## 开始一场投票

1. 首次使用请先按下文安装主持软件。在主持电脑启动[主持台](host/start.command)，打开[本机网页](http://127.0.0.1:8765)，记下六位入场码。启动时若列出[本机备用地址](http://[::1]:8765)，也可从这里打开。已运行旧版主持台时，可用原数据库重启新版。
2. 手机相机扫投票器屏幕上的二维码，确认加入设备热点。支持配网弹窗的手机可直接选网。若页面没有弹出，扫设备切换显示的第二个码，或打开[设备配网页](http://192.168.4.1/)。上下键可以切换两个码，热点名和备用密码显示在第一个码下方。
3. 在列表中选现场 2.4 GHz Wi-Fi，输入 Wi-Fi 密码和入场码，点「连接并入场」。开放网络会隐藏密码框，隐藏网络可手动输入名称。设备自动寻找主持电脑。同一网段有多个主持台时，手机会列出各台编号，点选与电脑一致的一项。设备收到主持台确认后才保存配置并重启。密码、入场码或发现失败都可以在原页重试。
4. 在主持台填写题目，选择「投票模式」和「截止方式」，点击「发起投票」。默认由主持人手动截止，也可选 30 秒、1 分钟、5 分钟，或指定某天的北京时间，精确到秒。参与者按上下键选择，按确定查看所选项，再按确定提交。确认页面按任一方向键可返回选择。设备显示「投票成功」表示电脑已记票。
5. 「截止收票」会停止接受新票，结果仍只对主持人可见。「公布结果」可以从收票中或已截止阶段执行。设备显示各选项票数、百分比和总票数，上下键可选中长选项滚动阅读。当前结果公布后即可发起下一题。

主持电脑与投票器应在允许互访的同一局域网，电脑可以使用网线。自动发现使用同一 IPv4 子网内的 UDP 48765，投票使用主持台的 TCP 端口（默认 8765）。发现报文只带随机查询值、公开会场编号和端口。投票器会记住配对的会场编号，同一主持电脑换 IP 或端口后可自动重新找到。不同电脑使用新数据库会有不同编号。要主动更换会场，长按确定键并确认重新配网。

若路由器过滤广播，或服务器仍是旧版，展开「手动指定主持电脑」，填私有 IPv4，例如 `192.168.1.20` 或 `192.168.1.20:9876`。电脑端在「参与设备」里可展开查看完整地址。若设备间被访客网络隔离，请改用允许设备互访的网络。手机因切换频道掉线时，可重连原投票器热点。

## 题库

点击新建投票或临时加题旁的「题库」，可以新建和编辑保存的题目。题目草稿填写完后，也可以点「存入题库」再保存一份。题库随会场的 SQLite 数据库保存在电脑上，桌面端和网页端使用同一个会场时可以共用。

点「选用题目」会把保存的题目载入当前投票表单。可继续调整标题、选项、投票模式和测验的正确答案，再发起或追加。题库修改会用于以后选用的题目，已经发出的投票保留当时的题目。

## 设置设备上限

在桌面端或网页主持台的「参与设备」中填写「设备上限」，点击「保存上限」。设置随会场数据库保存，收票中也可调整。增加名额后，新设备立刻可以登记。上限同时约束在线和离线的登记设备。缩容前可在「参与设备」中移除离线设备，直到已登记台数符合新的上限。主持台和投屏界面都会更新在线设备的上限。

## 投票模式

在每道题的编辑区选择「投票模式」。一场可以混用不同模式，收票中临时追加的题目也可以单独选择。每道题的模式在发出时确定。

| 模式 | 设置与计票 |
| --- | --- |
| 普通单选 | 自定义 2～6 项，按选项统计票数和比例。 |
| 赞成 / 反对 / 弃权 | 自动填写三个选项。赞成票过半即通过，以赞成与反对的票数之和为分母。弃权计入参与与总票数。赞成与反对票数相同则未过半，全弃权或零票时显示暂无表决结果。 |
| 五分评分 | 自动填写 1～5 分，主持台显示平均分和各分数的票数。 |
| 答题测验 | 自定义 2～6 项并选定正确答案，主持台显示正确答案、答对人数和答对比例。 |

四种模式均可用现有 AI Passport 投票器作答，每机每题确认一个选项。公布后投票器显示各选项票数，主持台和 CSV 还会记录每题的模式统计。

## 一次发起多题

在「新建投票」里填好第一题，点击「＋ 添加题目」继续填写。每题可设 2～6 个不同选项，一次最多 50 题。选好整组共用的截止时间，点击「一次发起 N 题」。页面会指出有问题的题号，修正后再发起，整批题目一起开放。

每台投票器按录入顺序从第一题开始。主持台保存本机这一票后，设备自动显示下一道未答题，各人按自己的速度作答。一机一题只计一票，重连或重启会从已保存的进度继续。0.4 固件会显示题号、总题数和已答数，最后一题提交成功后显示「本组已全部完成」。

主持台的「本组已收票」是各题的票数总和。用「实时计票 → 查看题目」切换各题，参与设备列表可查看每人的已答题数。「整组截止收票」和定时截止都会同时停止所有题收票。点「公布整组结果」后，投票器即可查看统计。0.4 设备按确定翻到下一题结果，长按上、下键可前后翻题。主持人也可选择一道题并点「在投票器上展示本题」，把相同结果同步给全场。已安装旧版固件的设备也能顺序作答，并跟随主持人查看结果。

## 收票中临时加题

在收票期间，主持台左侧显示「向本场追加题目」。填入题目和 2～6 个选项，点击「追加并推送」。新题排在本场末尾，沿用当前截止时间。单题场也可以继续加题，每场合计最多 50 题。

已答完的设备会立即收到新题。仍在作答的人先完成手头的题，重连后从自己的下一道未答题继续。新增题与原有题一起进入本场历史和 CSV。要预先准备另一场，可点击「准备下一场投票」，再点「返回本场追加题目」继续填写临时题。

## 定时收票

选择时长后从发题成功开始计时。选择「指定日期和时间」时，主持台始终按北京时间解释输入。收票中可以在「实时计票 → 调整截止时间」修改时间，或改回「手动截止」。在这里选择时长会从保存设置时重新计时。也可以随时点击「截止收票」提前结束。

主持台显示预定时刻和倒计时，0.3 版投票器在屏幕左上角显示剩余时间。设备通过主持台同步倒计时，无需配置时钟。到点时主持服务主动通知在线投票器，离线设备重连后取得最新阶段。已截止的题目不能延长或重开，点击「公布结果」后参与者才能看到票数。

关闭主持网页不影响截止。电脑休眠或服务停止期间不能接收新票。使用原数据库恢复后，已到期的题目直接进入截止阶段，未来的截止时间继续生效。旧数据库中的已有题目沿用手动截止；原有投票器连接新版主持台也会正常收到截止通知。设备端显示倒计时需要 0.3 固件。

## 桌面客户端与网页主持台

### 方式一：双击即用的原生桌面客户端（免装 Python）

项目内置跨平台原生桌面客户端入口 [host/desktop.py](host/desktop.py) 与打包配置 [desktop/gongxuan.spec](desktop/gongxuan.spec)，复用同一套主持服务与前端界面，支持四种投票模式、批量与追加题目、现场大屏投屏模式（快捷键 `F`）、实时字库校验、历史投票回顾复用、设备备注名及 CSV / 高清 PNG 结果图导出。

- **macOS 打包**：运行 `bash desktop/build_mac.sh`，生成可直接双击打开的 `dist/共选主持台.app`（及便携压缩包 `dist/共选主持台-macOS-<arch>.zip`）。数据默认保存在 `~/Library/Application Support/GongxuanVoting/votes.sqlite3`。
- **Windows 打包**：在 Windows 电脑双击或运行 [desktop/build_windows.bat](desktop/build_windows.bat)，生成免安装单文件 `dist\共选主持台.exe`（基于系统 Edge WebView2，无黑框控制台）。数据默认保存在 `%APPDATA%\GongxuanVoting\votes.sqlite3`。
- **CI 自动构建**：推送 `v*` 标签或在 GitHub Actions 手动触发 [build-desktop.yml](.github/workflows/build-desktop.yml)，可同时产出 macOS 与 Windows 双端成品。

如果本机的默认端口已经有共选主持台运行，桌面窗口会打开同一个会场，入场码和历史记录都可继续使用。若你同时运行不同会场，配网时可展开「手动指定主持电脑」，填写目标主持台「参与设备」里显示的局域网地址和端口，并使用该会场的入场码。

### 方式二：从源码直接运行

克隆本仓库并安装 Python 3.12，macOS 可直接双击 [host/start.command](host/start.command)，Windows 可直接双击 [host/start.bat](host/start.bat)（首次运行会自动建环境并打开页面）。也可在项目根目录手动执行：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r host/requirements-lock.txt
.venv/bin/python host/server.py
```

Windows 用 `py -3.12 -m venv .venv` 创建环境，后续两条命令中的 Python 路径用 `.venv\Scripts\python.exe`。参数 `--port` 可更改端口，`--data` 可选择另一场活动的数据库。主持管理页面仅在运行服务的电脑上开放。

## 计票与恢复

点击「发起投票」后，题目和选项会通过当前连接推送到在线投票器，主持台显示推送的台数。参与者可以立即选择并确认。收票期间才入场或重连的投票器会自动收到自己当前的题目。

每次手动截止、到达截止时间或直接公布结果，主持电脑都会在同一个数据库事务里保存本场统计。点「本场统计已保存，查看统计」或打开「投票历史」，可查看参与人数、总票数、每道题的选项票数及比例，也可下载 CSV。批量投票按场保存，参与人数按至少答过一题的投票设备去重。零票题也会保存。升级已有数据库时会补回历次统计，旧版未记录的结束时间显示为未知。查看历史或导出不会向设备公布结果。

在「投票历史」展开一场，点击「删除记录」并确认，即可移除整场归档。删除后，该场统计无法从历史中查看、复用或下载。刚结束的当前场次仍可在「实时计票」中公布。

| 情况 | 行为 |
| --- | --- |
| 提交时断线或断电 | 投票器在发包前将题号与选择写入 NVS。重启或重连时先取服务器快照，若仍为同一题且开放、服务器未记票，则自动补交原选择。 |
| 同一请求到达多次 | 电脑按「题号＋设备编号」唯一计票，相同选择返回原记录。改选请求会被拒绝。 |
| 截止时仍有未送达的请求 | 由主持电脑在计票事务取得写锁时判定。达到截止时刻即拒绝新票，重发已记票的相同选择仍可拿回原确认。 |
| 电脑服务重启 | 使用原数据库恢复当前题目、收票阶段、入场码和已记票，设备重连后同步。 |
| 设备登记名额已满 | 可在网页移除离线设备，再加入新设备。移除登记不会删票，同一设备重新入场仍受原投票记录约束。 |
| 零票或平票 | 零票显示 0%，平票保留相同票数。网页显示一位小数，投票器显示四舍五入的整数百分比。 |

数据库默认在 `host/data/votes.sqlite3`。需复制数据库时先停止服务，或用 SQLite 的备份接口。现场采用共享入场码和出厂 Wi-Fi MAC 识别设备，适用于可信局域网。多人共用入场码不提供防冒名的身份认证。Wi-Fi 凭据由投票器保存在本机 NVS。

## 中文界面

题目最多 60 字，每个选项最多 24 字。设备与主持台共用 6,994 个可显示字符，包括 GB2312 的 6,763 个汉字、可打印 ASCII 及常用标点。超出范围的字符会在发题时标出。长题目和选中选项会自动滚动。屏幕右上角显示电量，读不到时显示缺省标记。投票时闲置 30 秒、配网时闲置 60 秒会调暗屏幕，调暗后的首个按键仅点亮屏幕。

字体为 18 px、4 bpp 的思源黑体 SC 子集，资源、许可证和生成记录在 [字体资源目录](assets/fonts/)。重新生成需要 `lv_font_conv@1.5.3` 与 `fonttools==4.61.1`。

```sh
python3 tools/gen_vote_font.py generate --font assets/fonts/SourceHanSansSC-Regular.otf --converter /path/to/lv_font_conv.js
python3 tools/gen_vote_font.py check
```

## 验证与刷写

安装上文的主持软件依赖并激活 ESP-IDF 5.5.3，然后在项目根目录运行以下命令。

```sh
./tools/validate.sh
python3 tools/render_vote_preview.py
```

`./tools/validate.sh` 运行投票与发现测试，包括十端计票、定时截止、掉线重连和旧库迁移。它还核对字体、测试镜像校验工具，用隔离配置构建固件并验证合并镜像。只构建固件可运行 `./tools/validate.sh --firmware`。预览脚本用固件实际采用的 LVGL 和字体生成截图，输出在 `build/vote-preview/`。安装 Playwright 和 Chrome 的开发机还可用 `node tools/test_vote_browser.cjs` 检查网页操作与桌面、手机布局。手机相机扫码和系统配网弹窗需实机验证。

ESP32-C3 的 8 MB Flash 使用原 BSP 与原分区表。交付镜像为 `build/FoloToy-AI-Passport-full.bin`，起始地址为 **0x0**。匹配的 ELF、MAP、各段镜像及 SHA-256 清单在 `build/firmware/<合并固件SHA256>/`。复核命令为 `python3 tools/archive_firmware.py verify <目录>`。

0.1 至 0.4 使用相同的分区和配置结构。保留旧配网信息升级时，可从匹配的归档中仅把应用镜像写入本项目的应用偏移 `0x10000`。原固定地址继续有效，重新配网后可启用按会场自动发现。从 0x0 写入合并镜像可能重置 NVS。须取得本次刷机确认后才写入。实机验收先用一台检查启动、实体三键、中文、电量、配网、自动换题、倒计时与掉线，再用三台跑完整流程，最后用十台检查同时投票及长时间运行。串口日志提供空闲堆、最大连续块和主任务栈余量。
